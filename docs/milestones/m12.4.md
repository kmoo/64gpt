# M12.4 — Redundancy ablation: real progress, still short of the gate

**Status: LANDED (2026-07-26) as a code/test commit — NOT a ROM/model
release.** What shipped: the ablation (code + finding). What did NOT
ship: a model that clears the coherence gate — closer than M12.3, and
better than M12.2, but not there yet. Depends on M12.3
(`docs/milestones/m12.3.md`).

## What we tried

M12.3's leading (unconfirmed) hypothesis: D:/M: attribute columns
regressed coherence because they duplicate information already in the
text prefix, creating a training-dynamics asymmetry (columns held
"on" for every timestep of the whole unroll) without adding anything the
model didn't already have access to. This milestone tests that directly:
same corpus, same architecture, same training code as M12.3
(`model.CharGRU` with the widened one-hot input, `train_corpus_
conditioned_attr`, `qat_finetune_attr`, `ref_impl.generate_sampled_attr`)
— the ONLY change is `npc_service.strip_prompt_fields()` removing D:/M:
from the text prefix the model actually sees. Attribute ids are still
parsed from the ORIGINAL (unstripped) prompt string, so the columns
become the SOLE source of that signal instead of an echo of it.

`trainer/m12_4_attr_ablation_spike.py` — same host-only discipline as
M12.3 (fp32 train + int8 `quantize()`/`ref_impl`, no blob/kernel/ROM
artifacts), same coherence-probe methodology.

## The result: better, not there

| | invented/line |
|---|---|
| M12.1 gate (target) | ≤ 1.00 |
| **M12.4 (D:/M: stripped from prefix, columns only)** | **1.44** |
| M12.2 (prefix-only, no attribute conditioning) | 1.65 |
| M12.3 (D:/M: in BOTH prefix and columns) | 2.33 |

Per group: selena 0.62, cast 1.12, shadewrath 1.25, elowen 1.88, guard
1.75, korrath 2.00 — selena and cast already individually clear the
gate; guard and korrath are the laggards.

**This supports the redundancy hypothesis:** removing the duplicate
signal recovered most of M12.3's regression and even improved on
M12.2's plain-prefix approach by 13%. Training was also visibly
healthier than M12.3's: QAT *improved* several times (0.1344→0.1274 at
its eventual best) instead of degrading monotonically the way M12.3's
did. Still, **1.44 > 1.00 — the decision gate says no blob/kernel work
yet.**

## What DID land

- `npc_service.strip_prompt_fields(prompt, keys)` — removes named
  colon-tokens from a prompt string, tested (round-trips with
  `parse_prompt_fields`, identity on empty keys, exact-removal case).
- `trainer/m12_4_attr_ablation_spike.py` — reuses M12.3's model/training/
  ref_impl code unchanged; only the corpus-preprocessing step differs.
- `trainer` pytest green (207 passed, 3 deselected slow); no C++ touched.

   (2.00) are pulling the average up. Worth checking whether those two

   close the remaining ~0.44 gap.

   iterating on a promising direction" than "try something else
   entirely" — different posture than M12.3's result warranted.
