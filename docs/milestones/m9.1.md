# M9.1 — density-structure experiment: repetition pattern vs. total volume

**Status: INVESTIGATED, inconclusive/negative for the tested hypothesis.**
A same-day follow-up to M9's open coherence gap, prompted by a specific
question raised during M9's own retrospective: M9's shipped
`cast_corpus.py` and M8's proven-working guard corpus hit similar total
character volume (~120-146K chars/character) via opposite repetition
structures. Does the *structure* matter, independent of total volume?

## The question

M8's guard corpus: **NARROW** — a small combo space (~45 combos/instance)
repeated many times (`GUARD_PER_COMBO=24`).
M9's shipped cast corpus: **WIDE** — a large combo space (240 combos:
6 relationship tiers × 5 moods × 8 contexts), each repeated only
`per_combo=3` times.

Both land around the same total character count. Guard trains cleanly;
M9's cast still garbles some of the time. If repetition structure (not
just volume) matters, a NARROW-structured M9 corpus at the same total
volume should measurably outperform the shipped WIDE one.

## Method

`trainer/m9_1_density_experiment.py`: trains the M9 cast corpus **alone**
(no Selena/guard mixed in, unlike production `make_m9_blob.py`) so each
variant trains in minutes instead of ~30. This isolates the repetition-
structure variable but introduces a real confound, disclosed up front:
absolute output quality here is *worse* than the shipped model's, because
the shipped model benefits from Selena's 5MB corpus teaching it English
spelling generally — this experiment removes that entirely. The
WIDE-vs-NARROW *comparison* should still be fair since the confound
applies equally to both.

- **WIDE**: `cast_corpus.generate_pairs(seed=0)` — the shipped structure,
  240 combos/character × per_combo=3. 2,160 pairs, 397KB.
- **NARROW**: `cast_corpus.generate_pairs(seed=0, combo_count=10,
  per_combo=70)` — a new `combo_count` parameter (added this session)
  restricts each character to a seeded random subset of 10 combos,
  repeated 70 times each to land at a comparable total. 2,100 pairs,
  387KB.
- Both trained H=320, same seed, same gradient-clipped
  `train_corpus_conditioned`, combo-level val split (10% of each
  variant's own distinct combos held out — a fixed absolute holdout
  count would have been fine for WIDE's 240 combos but ate most of
  NARROW's ~30, a bug caught and fixed before running: see
  `combo_split()`'s fraction-based holdout).

## Result

| Variant | Final val loss | Eyeball read |
|---|---|---|
| WIDE (shipped structure) | 0.1980 | Mixed — some clean full sentences, some garbled |
| NARROW (guard-like structure) | **0.1894** (better) | More consistently garbled throughout |

The numeric result and the qualitative read **disagree**. NARROW's val
loss is lower, but its generated text reads worse by direct human
inspection:

```
NARROW: "I DON'T NICES. HEYST ON MY MEND A DON, OF GHEN."
NARROW: "STRYE'S RUSTY SWORD? CAN I SAY SOMETHING? YOU'RE PART A GOTON
         WALKS INTO A EVEREDING MY ALLE."
WIDE:   "EVERYONE MISSES SOMETIMES. EVEN YOU. ESPECIALLY YOU, HONESTLY.
         THIS HIDEOUT ISN'T ON ANY MAP. YOU'RE PART OF THE FAMILY HERE."
```

## Interpretation

**Likely explanation, not fully confirmed**: NARROW's validation set is
drawn from the same ~30-combo pool as its training set (only 10 combos
per character to begin with). A "good" val loss there plausibly reflects
memorizing a small, repetitive space rather than genuine generalization
— a number that looks better without meaning better output. This is the
same failure mode this project has hit repeatedly at every prior
milestone (val loss, int8-vs-float agreement, and LLM-judge scores have
each, at different points, looked fine while the actual text was
garbled) — not a new lesson, but a fresh, concrete instance of it.

**This experiment does not confirm the repetition-structure hypothesis.**
If anything, the eyeball evidence leans the opposite direction from what
was predicted. It doesn't cleanly refute it either — the missing-Selena
confound and the small, non-independent val set both weaken how much
weight either number should carry. Recorded here as a real, honest
negative/inconclusive result rather than silently dropped.

## What this doesn't rule out

- **Total volume might matter more than structure.** Neither variant
  tested here comes close to Selena's own ~5MB single-character corpus.
  A cast corpus at that scale (not just guard's ~120-146K/character) is
  untested.
- **The missing-Selena confound may be doing more work than the
  structure variable.** A cleaner test would run both variants inside
  the full production mix (Selena + guard + M9 cast), not isolated —
  at the cost of the full ~30min training time per variant instead of
  minutes.
- **A genuinely different repetition pattern** (e.g., a small number of
  fixed catchphrase-style lines repeated verbatim per combo, rather
  than assembled fresh from phrase banks each time) wasn't tested here.

## Next steps (not done this session)

1. Re-run this same WIDE-vs-NARROW comparison **inside the full
   production mix** (with Selena/guard), accepting the ~30min-per-variant
   cost, to remove the missing-Selena confound before trusting either
   result.
2. If volume (not structure) turns out to be the real lever, test a
   cast corpus scaled toward Selena's own ~5MB/character density rather
   than guard's ~120-146K.
3. Feeds directly into the still-open M9 DoD item (full capacity-dilution
   density sweep, `docs/plan.md` Known follow-ups) — this was a fast,
   narrow probe of one specific sub-question, not that full sweep.
