# M12.1 — The coherence rescue (Phase 2 DONE, hardware-verified)

**Status: Phases 1-2 DONE (2026-07-23–24), phases 3-4 not started.**
Depends on M12
(`docs/milestones/m12.md`), whose honest negative — 10x capacity, same
garbling — closed the last of the three previously-hypothesized
coherence levers. Full diagnosis, experiment data, and rationale:
**`docs/ideas-coherence-rescue-plan.md`** (the accepted plan; read it
first). This file tracks execution.

## The one-paragraph why

A controlled decoding experiment on M12's own cached model decomposed
the garbling into three multiplicative causes, none of which is
capacity: **int8 post-training quantization** (5 invented words in
float-greedy → 17 in int8-greedy on a 12-prompt probe — the largest
single cause), **unconditional per-character sampling** (17 → 22, with
144 forced off-argmax draws), and a **75:1 per-character training-data
skew** (Selena 36,000 pairs vs Elowen 480 — the starved characters
garble even in float). A fourth, meta-cause let three milestones miss
this: val loss is teacher-forced, prefix-masked, and float — blind to
all three by construction. M12.1 fixes each cause and ships on H=320
(capacity exonerated pending a de-noised re-test; 44 ch/s restored).

## Baseline (phase 1, M12 H=1024 cached model, 48 lines, seed 0xC0FFEE)

| character | pairs | invented/line | EOS-before-cap | verbatim |
|---|---|---|---|---|
| selena | 36,000 | 1.12 | 100% | 50% |
| guard | 4,320 | 1.62 | 100% | 25% |
| cast (9 chars) | 6,480 | 2.25 | 100% | 0% |
| shadewrath | 2,880 | 4.38 | 100% | 0% |
| korrath | 1,440 | 2.50 | 100% | 0% |
| elowen | 480 | 3.75 | 100% | 0% |
| **ALL** | 51,600 | **2.60** | 100% | 12% |

The pair-count gradient predicts the garbling rate almost monotonically
(Selena 1.12/line → Elowen 3.75/line), and only the two best-fed groups
ever produce a verbatim authored line at shipped sampler settings. This
48-line table is the number phases 2-4 must drive toward 0. (EOS
reliability was 100% in this sample — the run-to-cap failure mode seen
in the 12-prompt diagnosis experiment is real but rarer than garbling;
the probe tracks it in case a later phase regresses it.)

## Phase 2, run 1 (2026-07-24): QAT vindicated, gate redesigned, cast gap found

First H=320 retrain (QAT + rebalance v1): float phase early-stopped at
val loss 0.1141; QAT fine-tune then reached **0.1023 through the
quantized forward** — better than M11.1's float-forward 0.1015, i.e.
the shipped int8 model now outscores the old *pre-quantization* model.
Probe results vs the M12 baseline (48 lines, shipped settings):

| group | M12 (inv/line) | run 1 | note |
|---|---|---|---|
| selena | 1.12 | 0.00 | |
| guard | 1.62 | 0.00 | |
| elowen | 3.75 | 0.12 | 480 → 5,760 pairs |
| korrath | 2.50 | 0.38 | |
| shadewrath | 4.38 | 0.50 | |
| cast | 2.25 | **2.25** | untouched by rebalance — see below |
| **ALL** | **2.60** | **0.54** | |

Greedy control: **float 0, int8 0 invented words** (M12: 5 and 17) —
the quantization damage is fully closed.

**Two lessons, both acted on in run 2:**

1. **The 0.995 agreement gate FATALed this model — wrongly.** Post-QAT,
   agreement-with-the-float-parent stops being ground truth: QAT lets
   the float weights drift wherever, so long as the rounded version
   behaves (agreement measured 0.9839 while int8 greedy inventions were
   0, identical to float). Agreement is demoted to a catastrophic-only
   sanity floor (0.95); quality is now gated on the probe itself
   (ALL ≤ 1.0 inv/line) and greedy int8-vs-float parity (int8 ≤ float
   + 2 on 24 lines). The gate that failed was measuring the fix's
   mechanism, not its outcome.
2. **The town cast was the one group the rebalance never touched**
   (cast_corpus default per_combo=3 → 720 pairs/char across 9 chars —
   by then the thinnest slice in the corpus) and the one group that
   didn't improve. Cleanest confirmation yet that pairs-per-character
   is the controlling variable. Run 2: cast per_combo 3 → 12
   (2,880/char), selena 100 → 96, worst per-character ratio now
   exactly 4.0:1.

## Phase 2, run 2 (2026-07-24): gates pass, blob shipped

Cast rebalanced (720 → 2,880 pairs/char, 9 chars = 25,920 total pairs);
gate redesign from run 1 applied (agreement demoted to a 0.95 sanity
floor; quality gated on the probe + greedy parity). Result: **all gates
passed, blob written automatically.**

- QAT val loss (quantized forward): **0.1002** — better than both
  run 1 (0.1023) and M11.1's float-only baseline (0.1015). One float
  epoch-19→20 gradient spike (val loss 2.89 → 0.75, worse than run 1's
  spikes) fully recovered by epoch 25; best float checkpoint (0.1114,
  epoch 13) was never beaten again but restored correctly by early
  stopping — no manual intervention needed.
- Int-vs-float agreement: 0.9836 (informational only, per the run-1
  gate redesign) — comparable to run 1's 0.9839, confirming the
  redesign's premise: this number does not move much with more data or
  more QAT epochs, and was never the right quality signal.
- **Coherence probe (48 lines, shipped sampler settings) — ALL 0.50
  inv/line, gate was ≤ 1.0:**

  | group | pairs | M12 baseline | run 1 | run 2 |
  |---|---|---|---|---|
  | selena | 11,520 | 1.12 | 0.00 | 0.00 |
  | korrath | 5,760 | 2.50 | 0.38 | 0.00 |
  | guard | 4,320 | 1.62 | 0.00 | 0.50 |
  | elowen | 5,760 | 3.75 | 0.12 | 0.50 |

  plausible causes, not yet distinguished: (a) the cast spans **9**
  distinct characters sharing one slice of capacity, so per-character
  data is still thinner than the single-character groups despite the

- Greedy parity: float=1, int8=2 invented words across 24 lines (gate:

- Blob written: `game/rawfs/model.bin` (395,592 bytes), goldens/trace

## Engineering note: the RSP kernel became a build-time toggle, not a revert

Shipping H=320 meant un-doing M12's `RSP_H=1024` — but the K-chunked
kernel's DMEM/RDRAM tiling constants are hardcoded MIPS immediates
(`8192 = TILE_ROWS(8) * H(1024)`, a K-chunk loop count of `4`, etc.),
not parameterized assembly, so switching H is not a config flip at the
instruction level. Rather than overwrite M12's H=1024 kernel in git
history the way M12 itself overwrote M9's H=320 kernel (which is
exactly what would make a future phase-6 capacity re-test expensive to
re-derive), both hardware-verified kernel bodies now live side by side,
byte-for-byte unchanged (diffed at splitout time):

- `game/src/user/rsp_ngpt_h320.inc` — the M9-proven kernel (verbatim
  from commit `696e2e6`, pre-M12)
- `game/src/user/rsp_ngpt_h1024.inc` — M12's K-chunked port (verbatim)
- `game/src/user/rsp_ngpt.S` — now a thin `#include` dispatcher, keyed
  on `NGPT_RSP_H` (compiles via cpp — n64.mk's `.S` rule already runs
  RSP ucode through `$(N64_CC)`, confirmed by reading
  `$HOME/pyrite64-sdk/include/n64.mk` rather than assuming)
- `game/Makefile.custom`: `NGPT_RSP_H ?= 320`, threaded into BOTH
  `RSPASFLAGS` (picks the kernel body) and `N64_CXXFLAGS` (so
  `DialogueDemo.cpp`'s `RSP_H` buffer-sizing constant reads the SAME
  value — one source of truth instead of two hand-maintained constants
  that could drift, which is exactly the class of risk M12's own
  human-sign-off requirement on `NGPT_GRU_MAX_HIDDEN` was guarding
  against)

Switching capacity for a future phase-6 experiment is now `make
NGPT_RSP_H=1024` (or the Makefile.custom default), not a git-history
excavation + hand re-port. `core/ngpt.h`'s `NGPT_GRU_MAX_HIDDEN` stays
at 1024 unconditionally — it's a ceiling costing ~2KB
(`ngpt_ctx.h[MAX_HIDDEN]`) regardless of which RSP kernel is active, so
it doesn't need to move with the toggle.

artifact. Booted clean in Ares:

## Decisions on record

- **H=320 is the shipping config.** Both kernels are preserved and
  toggleable (`NGPT_RSP_H`, see above); H>320 needs a phase-6 win on a
  de-noised metric to buy its speed/RDRAM cost (H=1024: ~5 ch/s, 3MB
  rspWhh in 4MB RDRAM).
- **The 0.95 agreement gate is retired as a QUALITY gate, kept as a
  sanity floor.** 3 flips per 100 chars was never "safe" as a passing
  bar; it was calibrated on M4-era memorization models and silently
  stopped meaning anything. Post-QAT, agreement-with-float is
  additionally the WRONG signal on its own terms (QAT deliberately lets
  float weights drift so their rounded version behaves) — quality is
  now gated on the coherence probe + greedy parity.
- **No new corpus authoring.** Rebalance is ratio-only (per-combo
  counts), except town cast's per_combo which needed raising from its
  low default; the template banks are not the bottleneck.
