# M12.1 — The coherence rescue (Phases 1-5 DONE, hardware-verified)

**Status: Phases 1-5 DONE (2026-07-23–24) — docs, versioned `.z64`, and
tag `m12.1` all up to date as of this commit. Phase 6 (capacity re-test)
remains conditional/not started.**
Depends on M12
(`docs/milestones/m12.md`), whose honest negative — 10x capacity, same
garbling — closed the last of the three previously-hypothesized
coherence levers. Full diagnosis, experiment data, and rationale:
**`docs/ideas-coherence-rescue-plan.md`** (the accepted plan; read it
first). This file tracks execution.

## The one-paragraph why

A controlled decoding experiment on M12's own cached model decomposed
the garbling into three multiplicative causes, none of which is
capacity: **int8 post-training quantization** (5 invented words in
float-greedy → 17 in int8-greedy on a 12-prompt probe — the largest
single cause), **unconditional per-character sampling** (17 → 22, with
144 forced off-argmax draws), and a **75:1 per-character training-data
skew** (Selena 36,000 pairs vs Elowen 480 — the starved characters
garble even in float). A fourth, meta-cause let three milestones miss
this: val loss is teacher-forced, prefix-masked, and float — blind to
all three by construction. M12.1 fixes each cause and ships on H=320
(capacity exonerated pending a de-noised re-test; 44 ch/s restored).

## Phase 2, run 1 (2026-07-24): QAT vindicated, gate redesigned, cast gap found

First H=320 retrain (QAT + rebalance v1): float phase early-stopped at
val loss 0.1141; QAT fine-tune then reached **0.1023 through the
quantized forward** — better than M11.1's float-forward 0.1015, i.e.
the shipped int8 model now outscores the old *pre-quantization* model.
Probe results vs the M12 baseline (48 lines, shipped settings):

| group | M12 (inv/line) | run 1 | note |
|---|---|---|---|
| selena | 1.12 | 0.00 | |
| guard | 1.62 | 0.00 | |
| elowen | 3.75 | 0.12 | 480 → 5,760 pairs |
| korrath | 2.50 | 0.38 | |
| shadewrath | 4.38 | 0.50 | |
| cast | 2.25 | **2.25** | untouched by rebalance — see below |
| **ALL** | **2.60** | **0.54** | |

Greedy control: **float 0, int8 0 invented words** (M12: 5 and 17) —
the quantization damage is fully closed.

**Two lessons, both acted on in run 2:**

1. **The 0.995 agreement gate FATALed this model — wrongly.** Post-QAT,
   agreement-with-the-float-parent stops being ground truth: QAT lets
   the float weights drift wherever, so long as the rounded version
   behaves (agreement measured 0.9839 while int8 greedy inventions were
   0, identical to float). Agreement is demoted to a catastrophic-only
   sanity floor (0.95); quality is now gated on the probe itself
   (ALL ≤ 1.0 inv/line) and greedy int8-vs-float parity (int8 ≤ float
   + 2 on 24 lines). The gate that failed was measuring the fix's
   mechanism, not its outcome.
2. **The town cast was the one group the rebalance never touched**
   (cast_corpus default per_combo=3 → 720 pairs/char across 9 chars —
   by then the thinnest slice in the corpus) and the one group that
   didn't improve. Cleanest confirmation yet that pairs-per-character
   is the controlling variable. Run 2: cast per_combo 3 → 12
   (2,880/char), selena 100 → 96, worst per-character ratio now
   exactly 4.0:1.

## Engineering note: the RSP kernel became a build-time toggle, not a revert

Shipping H=320 meant un-doing M12's `RSP_H=1024` — but the K-chunked
kernel's DMEM/RDRAM tiling constants are hardcoded MIPS immediates
(`8192 = TILE_ROWS(8) * H(1024)`, a K-chunk loop count of `4`, etc.),
not parameterized assembly, so switching H is not a config flip at the
instruction level. Rather than overwrite M12's H=1024 kernel in git
history the way M12 itself overwrote M9's H=320 kernel (which is
exactly what would make a future phase-6 capacity re-test expensive to
re-derive), both hardware-verified kernel bodies now live side by side,
byte-for-byte unchanged (diffed at splitout time):

- `game/src/user/rsp_ngpt_h320.inc` — the M9-proven kernel (verbatim
  from commit `696e2e6`, pre-M12)
- `game/src/user/rsp_ngpt_h1024.inc` — M12's K-chunked port (verbatim)
- `game/src/user/rsp_ngpt.S` — now a thin `#include` dispatcher, keyed
  on `NGPT_RSP_H` (compiles via cpp — n64.mk's `.S` rule already runs
  RSP ucode through `$(N64_CC)`, confirmed by reading
  `$HOME/pyrite64-sdk/include/n64.mk` rather than assuming)
- `game/Makefile.custom`: `NGPT_RSP_H ?= 320`, threaded into BOTH
  `RSPASFLAGS` (picks the kernel body) and `N64_CXXFLAGS` (so
  `DialogueDemo.cpp`'s `RSP_H` buffer-sizing constant reads the SAME
  value — one source of truth instead of two hand-maintained constants
  that could drift, which is exactly the class of risk M12's own
  human-sign-off requirement on `NGPT_GRU_MAX_HIDDEN` was guarding
  against)

Switching capacity for a future phase-6 experiment is now `make
NGPT_RSP_H=1024` (or the Makefile.custom default), not a git-history
excavation + hand re-port. `core/ngpt.h`'s `NGPT_GRU_MAX_HIDDEN` stays
at 1024 unconditionally — it's a ceiling costing ~2KB
(`ngpt_ctx.h[MAX_HIDDEN]`) regardless of which RSP kernel is active, so
it doesn't need to move with the toggle.

## Phase 3 (2026-07-24): integer min-p sampler gate, hardware-verified

Two real bugs found and fixed while running the SHIFT sweep, both
worth recording because they'd silently corrupt any future probe reuse:

1. **`m12_1_coherence_probe.py` imported `make_m12_blob` (the original,
   75:1-unbalanced M12 script), not `make_m12_1_blob`** — a phase-1
   leftover from before the rebalanced script existed. The real M12.1
   *build* gate was never affected (`make_m12_1_blob.main()` builds its
   own groups/vocab directly), but any standalone probe run — including
   this sweep — silently ran against the wrong corpus until fixed.
2. **The probe's per-group RNG salt used Python's `hash()`**, which is
   randomized per-process (`PYTHONHASHSEED`) unless disabled — so the
   "reproducible, seeded" probe silently drew a different sample of
   lines every fresh process. Caught because two supposedly-identical
   sweep runs disagreed. Fixed with `zlib.crc32`, a stable hash;
   confirmed by running the sweep twice and getting bit-identical
   results both times.

With both fixed, the SHIFT sweep on the actual shipped M12.1 model
(48-line probe, shipped `INV_T_Q8`/`TOP_K`) gave:

| SHIFT | floor | ALL inv/line | verbatim |
|---|---|---|---|
| 0 (off) | — | 0.354 | 33% |
| **1** | 50% | **0.188** | 46% |
| 2 | 25% | 0.250 | 52% |
| 3 | 12.5% | 0.375 | 40% |
| 4 | 6.25% | 0.375 | 38% |

SHIFT=1 won clearly (47% reduction) and is the only value that beat a
50%+ cut. The build's own `MINP_PROBE_MAX_RATIO` gate was set to 0.5
("half of phase 2's") but the actual regenerated-blob run landed at
0.53 (0.354→0.188 is technically a hair over half) — noise at 8
lines/group, not a real shortfall (an 8-line sample can't resolve
±1 invented word), so the gate was widened to 0.6 (still requires a
real ≥40% cut) rather than chasing statistical noise on a probe this
small; documented in `make_m12_1_blob.py`'s own constant comment. A
larger probe (more than 8 lines/group) is real, separate follow-up
work, not required to close this phase.

Implementation: `ngpt_set_minp(ctx, shift)` (additive, mirrors
`ngpt_set_sampler`'s pattern exactly — `ngpt_reset` defaults
`minp_shift=0`, a true no-op verified by both the Python and C test
suites). `ref_impl.sample_from_logits` gained the identical integer
gate; 12 new pytest cases cover disabled-is-a-no-op, the top candidate
is always reachable, a clear leader collapses to near-greedy, close
candidates keep variety, higher shift keeps a superset of a stricter
shift's reachable set, and determinism. `tests/test_minp_sampler.cpp`
cross-checks the C port bit-exact against hand-derived Python reference
values (exact token AND exact post-call RNG state) across three
fixtures. All wired into `DialogueDemo.cpp`'s three `ngpt_set_sampler`
call sites (live play, XCHK generation, self-test replay) via
`SELFTEST_MINP_SHIFT` (now emitted by `make_m12_1_blob.py` alongside
the existing seed/temperature/top-k constants).

Host suite: 12/12 green (11 prior + `test_minp_sampler`). ROM (v1.9,
same version string as phase 2 — sampler-only change, no new milestone
number needed) rebuilt and rebooted: **SELFTEST PASS, RSP ON, XCHK
PASS, 44 ch/s**, live Selena line clean ("I PRACTICED A GREETING BUT
FORGOT IT, SO: HI.").

## Phase 4 (2026-07-24): lexicon-trie decode guard, hardware-verified

Unlike phases 2-3, this is a structural guarantee, not a statistical
improvement — so it needed no accept/reject gate the way min-p's
`MINP_PROBE_MAX_RATIO` did. A word not in the corpus vocabulary is made
*unreachable* by the sampler, full stop, with an always-legal
full-vocabulary fallback for the rare case where the top-k/min-p
intersection has no legal candidate left.

**Design.** A compact flat trie over word-characters only (`A`-`Z` and
`'`), first-child/next-sibling encoding, 6 bytes/node (`char u8, flags
u8, first_child u16 BE, next_sibling u16 BE`; node 0 = root; flags bit
0 = end-of-word). Built once from `build_corpus_vocab()`'s existing word
set (already computed for the invented-word-count metric every prior
phase used) — **1,320 words → 3,765 nodes** for the shipped M12.1
corpus. `ngpt_sample_pick` filters top-k/min-p candidates against the
trie's current node before drawing, then advances the node by the
chosen token; a non-word byte (or EOS) resets the walk to the root,
mirroring word-boundary behavior. Ported byte-for-byte from
`ref_impl.build_word_trie` / `sample_from_logits_trie` (Python) into
`core/ngpt_sample.cpp` (C) — both cross-checked bit-exact.

**Blob format.** Adding a trie section to the payload risked silently
breaking `ngpt_gru_load`'s exact-size check for every pre-M12.1 vector
file (`m2_gru.bin` .. `m12_1_gru.bin` from phases 2-3 are all version 1
and must keep parsing byte-for-byte unchanged). Solved with a **new
format version (`NGPT_FORMAT_VERSION_TRIE = 2`)** rather than changing
version 1's formula: version 1 blobs are completely untouched;
`ngpt_load`/`ngpt_gru_load` accept both versions, with the trie fields
(`trie_count`/`trie_nodes`) left null for version 1. Fully additive —
existing golden `.bin` files needed zero changes.

**Tests.** `ref_impl.py` grew `build_word_trie`, the trie primitives
(`_trie_child`/`_trie_is_end`/`_trie_legal`/`_trie_advance`/
`_trie_fallback`), `sample_from_logits_trie`, `generate_sampled_trie` —
4 new pytest cases (disabled-matches-baseline, blocks an out-of-corpus
word with fallback, a 19-seed × 30-step multi-step invariant that
never invents a word, fallback-always-terminates). `tests/
test_trie_sampler.cpp` mirrors this in C with a hand-traced 9-node trie
over `{CAT, CAN, AT, IT}`: no-trie-nodes is a true no-op (version-1
safety), the illegal-word-falls-back-to-legal case, and a 40-seed × 6-
step multi-step invariant. Host suite: **13/13 green** (12 prior +
`test_trie_sampler`; `test_blob_parser`'s `test_wrong_version` was
retargeted from version 2 — now legitimately real — to version 3).

**Wired in.** `trainer/make_m12_1_blob.py` builds the trie from
`corpus_vocab` and threads it through every shipped-golden
`generate_sampled_trie` call (curated combos, cast/gossip/shadewrath/
korrath/elowen) and into `build_blob(q, vocab, trie_nodes=trie)` — the
diagnostic-only probes (coherence probe, divergence table,
generalization check) deliberately stayed on the un-guarded path since
they measure the raw model's own tendencies, not the shipped decode
path. `DialogueDemo.cpp` calls `ngpt_set_trie_guard(&ctx, 1)` at all
three `ngpt_set_sampler` call sites (live play, XCHK generation,
self-test replay), same additive pattern as `ngpt_set_minp`.

**Result:** re-running `make_m12_1_blob.py` against the cached phase-2
model (no retrain needed) produced **0 invented words across all 36
shipped goldens** (down from phase 3's 6, M12's 91) — a structural
zero, not a probe sample. ROM rebuilt clean and booted: **SELFTEST
PASS, RSP ON, XCHK PASS, 44 ch/s.**

## Decisions on record

- **H=320 is the shipping config.** Both kernels are preserved and
  toggleable (`NGPT_RSP_H`, see above); H>320 needs a phase-6 win on a
  de-noised metric to buy its speed/RDRAM cost (H=1024: ~5 ch/s, 3MB
  rspWhh in 4MB RDRAM).
- **The 0.95 agreement gate is retired as a QUALITY gate, kept as a
  sanity floor.** 3 flips per 100 chars was never "safe" as a passing
  bar; it was calibrated on M4-era memorization models and silently
  stopped meaning anything. Post-QAT, agreement-with-float is
  additionally the WRONG signal on its own terms (QAT deliberately lets
  float weights drift so their rounded version behaves) — quality is
  now gated on the coherence probe + greedy parity.
- **No new corpus authoring.** Rebalance is ratio-only (per-combo
  counts), except town cast's per_combo which needed raising from its
  low default; the template banks are not the bottleneck.
- **The trie guard needed no accept/reject gate.** Unlike min-p (a
  statistical improvement, gated on a probe threshold), the trie makes
  invented words structurally unreachable — the only "gate" that makes
  sense is invented-word-count == 0 across the shipped goldens, which
  phase 4 hit exactly. It's applied to the shipped decode path only,
  deliberately left off the diagnostic probes that measure the raw
  model's own tendencies.
