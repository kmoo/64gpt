# M12.5 — FiLM conditioning: a third honest negative

**Status: LANDED (2026-07-26) as a code/test commit — NOT a ROM/model
release.** What shipped: the mechanism (code + tests + finding). What
did NOT ship: a model that clears the coherence gate — worse than
M12.4, worse even than M12.2. Depends on M12.4 (`docs/milestones/
m12.4.md`).

## What we tried

M12.4 closed most of M12.3's regression by removing the D:/M: prefix
redundancy, landing at 1.44 inv/line — real progress, still short of
the ≤1.00 gate. `docs/ideas-m12.3-conditioning-strategies.md`'s next
architectural candidate was FiLM (Feature-wise Linear Modulation, Perez
et al. 2017): instead of concatenating a one-hot attribute vector onto
the GRU's input every timestep (M12.2-M12.4's approach), FiLM predicts
a per-hidden-unit `(γ, β)` pair from the attribute vector once, then
applies `h' = γ⊙h + β` to the GRU's hidden state every timestep — a
more expressive mechanism, in principle able to modulate the whole
recurrence rather than just augment its input.

Implementation required `nn.GRUCell` + a manual per-step unroll instead
of batched `nn.GRU` (FiLM's modulation has to feed back into the
recurrence itself), landing as `CharGRUFiLM` (`model.py`),
`QuantizedGRUFiLM`/`quantize_film()` (`quantize.py`), and
`film_gamma_beta`/`gru_step_film`/`generate_sampled_film`
(`ref_impl.py`) — the same float→QAT→int8 pipeline shape as every
other conditioning mechanism in this line, proven bit-exact via a
synthetic overfit test (`trainer/tests/test_m12_5_film.py`, 7 tests)
before any real-corpus spend.

**A real numerical bug found and fixed before the real-corpus run
(not after):** an unbounded `γ = 1 + tanh(raw)` let the modulation
compound multiplicatively across the recurrence — even γ≈1.4-1.6, well
inside the naive (0,2) bound, squares past 2× per step and saturated
int16's Q14 range within 2 primed characters, producing degenerate
"HHHHH..." output on the *quantized* path while the float path looked
fine. Fixed with `FILM_SCALE = 0.2`, tightening the effective bound to
(0.8, 1.2)/(-0.2, 0.2) in both `model.py` and `ref_impl.py`
(`FILM_SCALE_Q14`). Caught by manual step-by-step h-value tracing, not
by the test suite failing loudly — worth remembering next time a
mechanism feeds a learned value back into its own recurrence.

## The result: worse, not better

| | invented/line |
|---|---|
| M12.1 gate (target) | ≤ 1.00 |
| **M12.4 (D:/M: stripped from prefix, columns only)** | **1.44** |
| M12.2 (prefix-only, no attribute conditioning) | 1.65 |
| **M12.5 (FiLM: γ/β modulate the hidden state)** | **2.15** |
| M12.3 (D:/M: in BOTH prefix and columns) | 2.33 |

Per group: guard 0.88, selena 1.62, cast 1.62, shadewrath 2.25, elowen
2.88, korrath 3.62 — guard is the only one still ahead of its M12.4
number; every other group regressed, korrath badly.

**FiLM did not help.** A more expressive, more literature-favored
mechanism than M12.4's plain input-concat approach produced a *worse*
result on this project's actual corpus and probe. Whatever's holding
guard/korrath back at this model scale, it isn't "the conditioning
mechanism needs more expressive power" — M12.4's simpler approach
remains the best result in this line.

**A real GPU crash happened mid-run, verified not to have contaminated
this result.** The float-training phase (`device="mps"`) collided with
an unrelated local-model server started later in the same session,
producing six `kIOGPUCommandBufferCallbackErrorOutOfMemory` errors and
a NaN val loss at epoch 85. `train_corpus_conditioned_film`'s own
early-stopping design — a CPU-cloned `best_state` snapshot kept in
memory, reverted to once patience expires (`nan < best` is always
`False` in Python, so NaN epochs correctly never overwrite it) —
recovered on its own: float phase finished at val loss 0.1276, matching
the last genuinely good epoch before the crash. No further GPU errors
occurred during QAT or the probe. Recorded honestly rather than
silently omitted; see the qwen-worker-14b-is-33b-bug memory for the
root cause (an unrelated tooling mistake, not a flaw in this
mechanism), and note for next time: this run had zero on-disk
checkpointing for its ~3 hour float phase — the only thing standing
between "fine" and losing that time was an in-memory value in a
process that nearly got killed. Worth adding periodic mid-run
checkpointing as a follow-up.

  207 — the 7 new FiLM tests).

## For M12.6 (and beyond)

M12.4 (1.44, input-concat, redundancy-ablated) remains the best result
in this line, still short of the ≤1.00 gate. Two mechanisms have now
been tried and both regressed on it (M12.3's redundant duplication,
M12.5's FiLM). Real candidates, none yet run:

1. **Corpus density on the laggards (still cheapest, still unclaimed):**
   M12.4 had guard/korrath as its two worst groups (1.75/2.00). Under
   FiLM, korrath got dramatically worse (3.62) but guard actually
   improved (0.88) — the two laggards no longer move together, which
   cuts against a single simple "thin corpus" story and is worth
   understanding directly (per-character density/reuse counts) before
   a fourth mechanism attempt, not after.
2. Given TWO architectural mechanisms (M12.3's duplication, M12.5's
   FiLM) have now both made things worse relative to M12.4's plain
   approach, the standing hypothesis shifts further toward "this is a
   corpus/data problem for the laggard characters, not a conditioning-
   mechanism problem" — M13's phrase-bank distillation work (`docs/
   milestones/m13.md`) is already aimed at exactly this gap and doesn't
   need to wait on a fourth mechanism attempt.
