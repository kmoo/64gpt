# M5 — Performance pass (ROM v1.0-rc, ≥30 chars/sec)

**Status: DONE (2026-07-16, tag `m5`).** 16,595 → 9,795 µs/step (1.7×):
raw 102 chars/sec, sustained 60 chars/sec at a held 60 VPS — 2× the
≥30 gate. Wins: `-O3` on core objects, int64→int32 accumulators in the
hot loops (bit-exactness unchanged, goldens the proof). Full numbers
and dead ends: `docs/07-performance.md`.

## Method

1. **Instrument first**: µs per `ngpt_step` (EMA) + derived raw chars/sec
   on the demo screen, via libdragon timers — game-side only, `core/`
   stays libdragon-free. Ares is the measurement bench (cycle-oriented,
   hardware-accurate class emulator); M6 spot-checks on the EverDrive.
2. **Baseline** before touching anything, screenshot the number.
3. **Optimize** in small steps, each gated by the full bit-exactness
   suite (host 5/5 + trainer + ROM SELFTEST PASS) — a "fast" engine that
   drifts one bit is a failed step. Candidates, cheapest first:
   - compiler: core objects from `-Os` (project default) to `-O2`/`-O3
     -funroll-loops` via `Makefile.custom` per-object flags
   - accumulator width: the hot matvec runs int64 accumulators on a
     32-bit-heavy pipeline; int32 suffices at H=128 dims (documented in
     ref_impl) — measure both
   - weight access: W_hh rows are already sequential; check the h[]
     reload pattern and LUT locality
   - RSP matvec: documented stretch goal, OUT OF SCOPE (plan.md)
4. **Gate**: ≥30 chars/sec with `CHARS_PER_FRAME` raised to match, 60
   VPS held, SELFTEST PASS on a clean build.

## Gotchas (what M6 should know)

- **Stale `game/filesystem/model.bin` after a tag checkout.** The cp
  rule compares mtimes at second granularity; a checkout-build-checkout
  cycle inside one second left the M3 blob in an M4 ROM (SELFTEST FAIL
  caught it — and the demo speaking M3's hand-written lines confirmed
  it). Milestone builds now purge `game/filesystem/` along with
  `game/build/`.
- **Boot self-test = ~1,000 steps of black screen** (~10s post-M5).
  Screenshot scripts must wait for it; M6's EverDrive checklist should
  mention the pause so nobody pulls the cartridge.
- **The overlay measures emulated ticks**, so Ares fast-forward (300
  VPS) doesn't distort µs/step.
