# M3 — Conditioning: a dozen hand-written lines (ROM v0.3)

**Status: DONE (2026-07-15, tag `m3`).** The GRU learns 12
prompt→response pairs; the prompt selects which line it speaks. ROM v0.3
boots in Ares with SELFTEST PASS replaying all 12 prompts. Shipped:
H=64, V=32, ~21K params, 23,218-byte blob — same type-1 format as M2.

## Architecture (signed off by Luke 2026-07-15)

**Text-prompt priming, blob format unchanged.** No new payload fields,
no API change — `ngpt_reset(ctx, model, prompt)` was frozen with this in
mind. Conditioning works by *priming*: on reset, the GRU consumes the
prompt characters teacher-forced (hidden state updates, nothing is
emitted, logits are skipped), then generation runs exactly as in M2.
The alternative (dedicated condition tokens = a format extension) buys
nothing until M4, which also drives with text prompts.

## Prompt protocol (exact, both sides must match)

- Prompt string: `NPC=<npc> MOOD=<mood> EV=<event>|` — uppercase
  (debug-font constraint), `|` is the prime/generate boundary and is
  part of the primed text.
- Training sequence per pair: inputs `EOS + prompt + response`, targets
  `prompt + response + EOS`, cross-entropy over the full sequence.
- Generation: `h = 0`; feed `EOS`, then each prompt char, updating `h`
  only (no argmax); after the final `|`, argmax-generate until EOS —
  identical to M2 from there.
- Unknown prompt characters at runtime are skipped (the demo builds
  prompts from the same string tables the corpus uses, so this is a
  belt-and-suspenders rule, not a feature).

## Corpus (3 NPCs × 2 moods × 2 events = 12 pairs)

NPC ∈ {GUARD, MERCHANT, WIZARD}, MOOD ∈ {ANGRY, CALM},
EV ∈ {THEFT, FESTIVAL}. Responses are hand-written, ≤ 40 chars,
uppercase, in `trainer/ngpt_trainer/corpus.py` (the single source —
the demo's string tables and the goldens all derive from it).

## Dims

`H = 64` (12 sequences need more memory than one), `V` = charset of
prompts + responses (≈ 35, still < 96 cap). ~21K params ≈ 22 KB blob —
same type-1 payload, only the dims fields differ.

## Gotchas (what M4 should know)

- **Dims doubled, stack didn't.** H=64 keeps the M2 rule alive: GRU
  scratch lives in statics, not on the N64 thread stack. Nothing to do
  in M4 beyond respecting the same rule at H≤128.
- **V=32, not ≈35.** The uppercase-only corpus plus prompt punctuation
  lands on a 32-char charset — comfortably under the 96 cap M4 needs.
- **Delegation lesson (task 003):** golden-vector bit-exact tests belong
  to the "never delegate" class. The local model invented an API and
  cast blob pointers to wider types (a hard-constraint violation) twice;
  the lead wrote the test directly. Contracts for M4 keep qwen on
  corpus-generation-style work, not verification kernels.
