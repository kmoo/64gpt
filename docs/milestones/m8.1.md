# M8.1 — Corpus authoring methodology: template grammar vs. LLM-generated lines (idea — not scoped)

**Status: IDEA, not planned/scoped.** Raised 2026-07-17 during M8's guard
corpus work. Not a hard dependency for M8 — this is a methodology
question that can be picked up whenever, using whichever corpus is
current at the time. **Update, same day:** M9 (compositional
conditioning, `docs/milestones/m9.md`) is where this actually gets
tested for real — M9's corpus needs many feature-combination lines
covered, which is a better fit for LLM generation than M8's per-
archetype template grammar, so M9's Engineering plan §4 commits to the
qwen-generation side of this question rather than leaving it a pure
hypothetical.

## The question

Every corpus in this project so far (`selena_corpus.py`, `guard_corpus.py`,
M4's `corpus_gen.py`) is a hand-written template grammar: fixed
OPENER/BODY/CLOSER pools, slot-filled and combined by a deterministic
RNG. That's cheap, fully reproducible, and easy to reason about — but
it's still a human (or a human relaying a personality sketch to qwen for
bulk lines, per M8's guard corpus) writing every sentence by hand inside
a fairly rigid skeleton. Does training on genuinely LLM-authored lines —
qwen generating full training pairs directly, not just filling slots in
a lead-authored template — produce a model whose *output* reads as more
natural human speech, versus the current template-grammar approach?

## Why it's worth asking

M8's own guard corpus work surfaced a relevant data point: an
all-4-guards-at-once qwen dispatch collapsed into near-duplicate lines
across characters, while isolated per-guard dispatches (one call, one
character, strong voice examples) produced genuinely distinct,
usable lines. That's a hint about *how* to prompt an LLM for corpus
content, not an answer to whether LLM-generated corpus content beats
template-grammar content once trained into the actual GRU. Worth
knowing before this project scales to a full cast (M10/M11) commits
further to one authoring method over the other.

## Sketch of how this would actually be tested

- Take one already-proven character or archetype (Selena, or a guard
  instance) as the fixed comparison point — same personality, same
  schema, same trust/mood/context grid.
- Corpus A: the existing template-grammar generator (status quo).
- Corpus B: qwen generates full (prompt, response) training pairs
  directly against the same voice sketch and schema constraints, at
  comparable volume — not filling a lead-authored skeleton, actually
  writing the lines end to end.
- Train two otherwise-identical models (same H, same holdout
  methodology), then compare using metrics this project already has:
  conditioning-ablation divergence (does the identity/mood signal still
  hold?), effective-diversity / repetition self-similarity ("feels
  generative" per the M7-era follow-up), and a human eyeball pass for
  naturalness — the thing template grammars are weakest at, since a
  slot-fill skeleton always has a detectable rhythm.
- If corpus B wins on naturalness without regressing the divergence
  gates, that's a real methodology change worth adopting project-wide,
  not just a one-off experiment.

## Open questions this doesn't answer yet

- Whether qwen (7B/14B local) is strong enough to write full training
  pairs unsupervised, or whether it still needs a human pass the way
  M8's guard OPENER/CLOSER lines did.
- What "comparable volume" means when one method is template-fill (near
  free, thousands of variants) and the other is per-line LLM generation
  (slower, needs verification each time).
- Whether the two corpora should be trained on the *same* character (to
  isolate the corpus-generation variable) or a fresh throwaway identity
  (to avoid touching Selena's or a shipped guard's live corpus) — the
  spike-identity precedent (`docs/spikes/identity-conditioning.md`)
  argues for a throwaway, not a shipped character.
