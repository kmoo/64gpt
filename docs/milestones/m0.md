# M0 — Environment + skeleton repo

**Status: repo skeleton done (remote session); toolchain install pending on the Mac.**

## What was built

- Repo layout: `core/` (inference engine), `tests/` (host tests + golden
  vectors), `trainer/` (Python tooling), `game/` (Pyrite64 project),
  `docs/` (you are here).
- README with the goal, the milestone checklist, and pinned versions.
- Concept docs `00-n64-primer.md` and `01-toolchain-and-pyrite64.md`.

## What it proves

That the project has a single verification loop everything else hangs
off: host tests → headless ROM build → Ares boot with on-screen
self-test. (The host-test leg is already alive; the ROM leg activates
once the toolchain is installed.)

## Decisions worth remembering

- **Pin pyrite64-mac to its latest tagged release** (v0.4.0 at time of
  writing; upstream is at v0.7.0). Early-dev engine, breaking changes —
  we upgrade deliberately, never accidentally.
- `core/` is C-style C++ in **`.cpp` files, kept flat** — both are hard
  requirements of Pyrite64's generated Makefile (only `.cpp` is
  compiled; directory symlinks are listed but not recursed into). We
  verified this in Pyrite64's source (`src/build/projectBuilder.cpp`,
  `data/build/baseMakefile.mk`), not just its docs.
