# CLAUDE.md — 64GPT project instructions

Tiny neural NPC dialogue brain (char-level GRU, ~100K params, int8) running
on a real Nintendo 64 via the Pyrite64 engine. Full plan, verified engine
facts, and current status: **`docs/plan.md`** — read it before starting any
milestone work. Per-milestone status and remaining checklists:
`docs/milestones/mN.md` — **`m6.md` doubles as the session-resume brief; `m6.1.md` is the
active build task (RSP-powered inference).** Forward-looking material: `docs/ideas.md`,
`docs/ideas-m7-living-npcs.md` (recorded vision), and `docs/spikes/`
(RSP matvec: proven bit-exact at 2.8x CPU, branch `spike/rsp-matvec`).

## The method (non-negotiable)

Walking-skeleton TDD. A bootable ROM ships at **every** milestone; each
milestone swaps in the smallest real piece (canned line → GRU on one line →
a dozen lines → full corpus). Never build AI parts in isolation to "port
later". Milestone definition of done, in order:

1. red tests → implement → green tests (host, and trainer pytest from M2)
2. ROM builds headlessly and boots in Ares showing **SELFTEST PASS**
3. docs written (concept guides + `docs/milestones/mN.md`) — **a milestone
   without its docs is not done**
4. README status checklist updated → commit → tag `mN`

Docs audience: a good software engineer with zero game-dev / zero embedded-ML
background. Explain why, not just what.

## Commands

```sh
# host tests — verified sequence on this Mac (macOS 26.5 + AppleClang 17:
# ASan deadlocks before main, so sanitizers off; rm build/ first so a stale
# sanitized CMake cache can't leak into the fresh configure)
rm -rf build
cmake -B build tests -DNGPT_SANITIZE=OFF && cmake --build build && ctest --test-dir build --output-on-failure

# regenerate model blob + golden vectors + ROM self-test header (one script = no drift)
python3 trainer/make_canned_blob.py

# ROM build (after one-time toolchain install, see docs/01-toolchain-and-pyrite64.md)
# ⚠ invoke the app binary by its REAL path — exec'ing it via a symlink breaks
# NSBundle's Resources/ lookup and every build template silently loads empty
# (0-byte generated game/Makefile → "make: No targets"). Any CWD works.
"$HOME/GitHub/Pyrite64-v0.4.0/Pyrite64.app/Contents/MacOS/pyrite64" \
  --cli --cmd build "$PWD/game/project.p64proj"   # → game/64gpt.z64, boot in Ares
```

## Public repo

This repo is public. Nothing private ever gets committed: no absolute
`/Users/<name>` paths (write `~` or `$HOME`), no emails, no machine-local
config (that goes in git-ignored `CLAUDE.local.md`). Check `git diff
--cached` for leaks before every commit, and again before any push.

## Hard constraints (violating any breaks the build or the bit-exactness proof)

- `core/` is the inference engine: **flat directory, `.cpp`/`.h` only** —
  Pyrite64's generated Makefile compiles only `*.cpp` and does not recurse
  into the `game/src/user/n64gpt` symlink. No subdirectories, no `.c` files.
- `core/` style: C-style C++. **No floats, no heap, no exceptions/RTTI, no
  libdragon includes.** Integer math only — this is what makes host tests
  prove N64 behavior.
- The `NGPT` blob is big-endian on the wire and parsed **byte-by-byte**
  (`ngpt_read_u16be/u32be`). Never cast buffer pointers to wider types.
  Format spec: `docs/03-blob-format.md`.
- Golden vectors (`tests/vectors/`), `game/rawfs/model.bin`, and
  `game/src/user/selftestGolden.h` are only ever regenerated by trainer
  scripts, never hand-edited.
- The streaming API (`ngpt_load → ngpt_reset → ngpt_step → NGPT_EOS`) is
  frozen. New model types go behind it via the blob's model-type field.
- Don't edit generated/editor-owned files: `game/data/`, `game/src/p64/`,
  `game/Makefile` (use `game/Makefile.custom`), `game/project.p64proj` only
  via the editor.
- Pin pyrite64-mac to its tagged release (see README); don't chase upstream.

## Toolchain notes

- Pyrite64 editor+CLI: mac fork `proverbiallemon/pyrite64-mac`, SDK in
  `$HOME/pyrite64-sdk`, Ares emulator installed by its Toolchain Manager.
- Python: stdlib-only scripts run with `python3`; from M2 the trainer uses
  uv with Python pinned to 3.12 (`uv python pin 3.12`) for PyTorch.
