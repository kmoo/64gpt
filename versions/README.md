# versions/ — built ROMs, one per milestone

Ready-to-run `.z64` images (EverDrive takes them as-is; see
`docs/hardware-checklist.md`). Each is the walking skeleton with a
progressively more real brain — together they tell the project's story
in cartridge form. All boot with an on-screen SELFTEST verdict; expect
~10s of black screen first on m4/m5-era ROMs (boot self-test).

| `m11_64gpt.z64` | `m11` | Town cast + Elowen (`docs/milestones/m11.md`) — the gossip mechanism (a player-caused event reaches nearby town NPCs' conditioning secondhand), 2 more town archetypes (merchant/healer), and Elowen, a rescued elf princess found in the dungeon (mid tier, dungeon-only, her own persisted trust tier). SELFTEST + XCHK PASS on screen for 36 goldens, RSP ON. **Honest negative result, shipped anyway**: the same retrain also carried this milestone's quality push (a shared Ravendale-lore bank meant to fix Shadewrath's/Korrath's standing coherence gap) — combining it with the new archetype/princess content in one retrain regressed rather than improved: agreement dropped 0.9771→0.9536, and garbling spread beyond Shadewrath/Korrath to previously-clean characters including Selena herself. Recorded plainly rather than reworked until it looked like a win — `docs/milestones/m11.md` has the full record and the retrospective correction to this project's own "one retrain covers all of it" precedent. M11.1 retries with proper single-variable isolation |
| `m11_1_64gpt.z64` | `m11.1` | Full genericization + isolated lore-bank retrain (`docs/milestones/m11.1.md`, v1.7) — every remaining old-scheme character (Selena, Shadewrath, Korrath, Elowen, and guard's 4 fixed instances) migrated onto `NpcService`'s compositional scheme; `ContextBuilder`/`N:<id>` deleted entirely, zero callers left. Three new conditioning axes added: `AUD:` (audience, alone/witnessed — operationalizes the manifest bible's public/private fields), `BOND:` (relationship type: stranger/ally/rival/enemy/captor/captive/family/mentor/romantic), `SPECIES:` (human/elf/dwarf/beast/shade). Then ran the controlled experiment M11's combined retrain made impossible: baseline (no Ravendale-lore bank) vs. treatment (with it), RNG-identical corpora except the lore clause's presence, against a bar pre-registered before either result was seen. **Result: the lore bank does not clear the bar** (invented-word count only 69→67 on a 26-golden probe, needed ≤34) — agreement and divergence both held fine, but the coherence gap didn't move. Second content-structure lever tried and found insufficient (after M10's density-fix attempt), strengthening the case that H=320 is a real capacity ceiling, not a corpus-authoring problem. Shipped baseline: val loss 0.1015, int8-vs-float agreement 0.9508, SELFTEST + XCHK PASS on screen for 36 goldens, RSP ON. Full record and pre-registered bar: `docs/milestones/m11.1.md`. |
| `m12_64gpt.z64` | `m12` | Capacity scaling (`docs/milestones/m12.md`, v1.8) — tests whether more model capacity fixes the standing coherence problem, the third and last lever on record after raw pair count (M10) and shared structural content (M11.1) both came back insufficient. `NGPT_GRU_MAX_HIDDEN` bumped 320→1024 with explicit sign-off (`core/ngpt.h` is a frozen interface), via a K-chunked RSP kernel ported from the hardware-verified `spike/rsp-matvec-ktile` branch onto current `main` (DMEM footprint matches the spike's own proven numbers exactly), plus an int64 overflow-mitigation on the CPU reference path (verified by a new host test). Trained M11.1's exact corpus/seed at H=1024 via MPS — capacity was the only controlled variable. **Result: also does not work.** Val loss landed *worse* than the H=320 baseline (0.1051 vs. 0.1015) — not just short of the all-time-low bar, behind the thing it was meant to beat. Agreement improved (0.9696) and divergence stayed healthy, but the garbling itself didn't move. All three levers this project has tried for the coherence problem are now exhausted; the working theory shifts to something other than capacity or corpus content being the bottleneck. Also found and fixed a real, previously-latent bug in the golden-recording pipeline (`generate_sampled()`'s `max_len=256` default was never overridden by any `make_mN_blob.py`'s own `MAX_GOLDEN_LEN`, silently truncating goldens past 256 characters — present since M11.1, never manifested until H=1024's longer output exposed it). SELFTEST + XCHK PASS on screen for 36 goldens, RSP ON, ~5 ch/s (an explicit, disclosed speed tradeoff, not a regression). Full record: `docs/milestones/m12.md`. |

Rebuild any of them from source: check out the tag/branch, purge
`game/build/` and `game/filesystem/`, then the ROM build command in the
root README. The spike ROM additionally requires the spike branch's
`Makefile.custom` ucode hook (already on that branch).
