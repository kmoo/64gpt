# game/ — the Pyrite64 project

This directory holds the N64 game that wraps the 64GPT engine. The parts
that are checked in:

| path | what it is |
|---|---|
| `src/user/DialogueDemo.cpp` | the demo script (self-test + streaming dialogue box) |
| `src/user/selftestGolden.h` | autogenerated golden bytes for the boot self-test |
| `src/user/n64gpt` | **symlink** to `../../core` — the inference engine, compiled into the ROM unchanged |
| `rawfs/model.bin` | the NGPT model blob (regenerate with `python3 trainer/make_canned_blob.py`) |
| `Makefile.custom` | packs `rawfs/model.bin` into the ROM filesystem |

The rest of a Pyrite64 project (`project.p64proj`, `data/`, `src/p64/`,
`assets/`) is created **once, on the Mac, in the editor** — see below.
Build artifacts (`build/`, `engine/`, `filesystem/`, `Makefile`, `*.z64`)
are generated and git-ignored.

## One-time project setup (on the Mac, after the M0 toolchain install)

1. Launch the Pyrite64 editor and create a **new project in this `game/`
   directory** (ROM name `64gpt`). Pyrite64 only creates files that are
   missing (`ensureFile`), so the checked-in `Makefile.custom` and
   `src/user/` contents survive.
2. Open the default scene, add an empty object, add a **Code** component,
   and select the `DialogueDemo` script (the editor picks it up from
   `src/user/` by the UUID stored in the file).
3. Save. Then build headlessly from a terminal:

   ```sh
   ./pyrite64 --cli --cmd build /path/to/64gpt/game/project.p64proj
   ```

4. Boot the resulting `.z64` in Ares. You should see `SELFTEST PASS`,
   the canned line streaming in, and A regenerating it.

If the editor refuses to create a project in a non-empty directory,
create it in an empty temp directory instead, then copy
`project.p64proj`, `data/`, and `src/p64/` in here — do not overwrite
the checked-in files listed above.
